# DM_DUEL v3 — мультиплеер: контракт

Дополняет [CONTRACT.md](CONTRACT.md). Все правила оттуда (§0) действуют и здесь:
один `<script>`, общая область видимости, three.js r128, никаких зависимостей и внешних
ассетов, ноль аллокаций в кадре, комментарии по-русски.

## 0. Что решено и не обсуждается

* **Режим:** PvP, две команды — BLU и RED. Свободные слоты добивают боты (нынешний ИИ).
* **Игроков:** до 4 (плюс боты до общего лимита `RULES.slots`).
* **Подключение:** локальная сеть и интернет через туннель. Сервер отдаёт и игру, и сокет.
* **Зависимостей нет.** WebSocket-сервер написан вручную (RFC 6455). Никакого `npm install`.

## 1. Модель авторитета

Полностью авторитетный сервер потребовал бы перенести туда рельеф, коллизии, баллистику
и ИИ — это переписывание половины проекта. Выбрана честная для четверых друзей схема:

| Что | Кто решает |
|---|---|
| Своё движение и паркур | клиент (нынешний код без изменений) |
| Попал или нет | **стреляющий клиент** — бьёт по тому, что видит на своём экране |
| Здоровье, смерть, респавн | **сервер** |
| Очки и счёт матча | **сервер** |
| Пикапы (кто успел) | **сервер** |
| Боты | один клиент — «хост ботов», остальные видят реплики |

Сервер **проверяет заявки**, а не пересчитывает мир: жив ли стрелок, жива ли жертва,
не превышен ли максимально возможный урон типа боеприпаса, соблюдён ли темп стрельбы,
правдоподобна ли дистанция. Это ловит рассинхрон и небрежное жульничество, но не претендует
на защиту от подготовленного читера — для игры с друзьями этого достаточно, и об этом
честно написано в интерфейсе.

## 2. Транспорт и темп

* WebSocket, текстовые кадры, одно JSON-сообщение на кадр: `{t:'тип', ...}`.
* Клиент → сервер, своё состояние: **20 Гц**.
* Сервер → клиенты, снапшот: **20 Гц**.
* Удалённые игроки и боты рисуются **с задержкой 120 мс** и интерполяцией между снапшотами —
  иначе на любом пинге они дёргаются.
* Пинг: сервер шлёт `ping`, клиент немедленно отвечает `pong`. Раз в 2 с.
* Клиент, замолчавший дольше 10 с, считается отвалившимся.

## 3. Сообщения

### Клиент → сервер

```
{t:'hello', name, ver}
{t:'move', s, x, y, z, yaw, pitch, h, f}      s — счётчик пакетов, f — флаги (см. §4)
{t:'shot', a, ox,oy,oz, dx,dy,dz, c}          a — индекс боеприпаса 0..2, c — заряд 0..1
{t:'hit',  v, p, d, a}                        v — id жертвы, d — урон,
                                              p — 'head'|'body'|'legs'|'splash'|'burn'
{t:'boom', x,y,z, a, h:[{v,d}]}               фугас: эпицентр и заявленные задетые
{t:'burn', v, d}                              подожжённый игрок
{t:'pick', i}                                 заявка на пикап с индексом i
{t:'bots', b:[...]}                           только от хоста ботов, формат — §5
{t:'bhit', v, d, p}                           урон игроку от бота (шлёт хост ботов)
{t:'resp'}                                    готов возродиться
{t:'pong', k}
```

### Сервер → клиент

```
{t:'welcome', id, team, k, goal, slots, host, players:[{id,name,team,hp,alive,kills,deaths}]}
{t:'join', id, name, team}
{t:'leave', id}
{t:'snap', k, p:[{i,x,y,z,yaw,pitch,h,f,hp,a}], b:[...]}    k — серверное время, мс
{t:'shot', i, a, ox,oy,oz, dx,dy,dz, c}       ретрансляция чужого выстрела (трассер и звук)
{t:'boom', x,y,z, a}                          чужой взрыв — только для эффектов
{t:'dmg',  from, d, hp, p}                    тебе прилетело; hp — авторитетное значение
{t:'kill', v, k, p}                           v — убитый, k — убийца (-1 если огонь/падение)
{t:'hit', i, v, p, d, a}                      пересылка заявки об уроне боту хосту; i — кто стрелял
{t:'resp', i, x,y,z}
{t:'score', blu, red, s:[{i,k,d}]}
{t:'pick', i, by, at}                         at — серверное время возврата пикапа
{t:'host', i}                                 назначен новый хост ботов
{t:'ping', k}
{t:'err',  m}
```

Неизвестный тип сообщения обе стороны обязаны молча игнорировать — это точка роста протокола.

## 4. Флаги состояния `f` (битовая маска)

```
1 присед   2 подкат   4 лестница   8 трос   16 оптика   32 рывок   64 на земле   128 подтягивание
```

## 5. Боты

Хост ботов — клиент с наименьшим id. При его уходе сервер шлёт `host` следующему.

* Хост симулирует ботов нынешним кодом `70_ai.js` и шлёт `{t:'bots', b:[...]}` 20 раз в секунду.
* Формат бота: `{i, x, y, z, yaw, pitch, h, st, a}` — `i` индекс, `st` код состояния, `a` жив.
* Остальные клиенты **не симулируют ботов**: `enemies` у них — реплики, которые двигаются
  интерполяцией по снапшотам. Логика ИИ у не-хоста отключена.
* Урон игроку от бота заявляет хост (`bhit`); урон боту от игрока считает стрелявший клиент
  локально и шлёт `hit` с `v` вида `'b'+индекс` — сервер пересылает хосту, тот применяет.

## 6. Клиентский API

### `src/92_net.js` — транспорт и протокол (агент **N2**)

```js
const NET = {
  on:false, id:-1, team:0, host:false, ping:0, goal:20,
  botCount:0,                  // сколько ботов держит комната (свободные слоты)
  players:new Map(),           // id -> {id,name,team,hp,alive,kills,deaths,buf:[],ent:null}
  connect(url, name),          // -> Promise, резолвится на 'welcome'
  disconnect(reason),
  send(obj),
  update(dt),                  // зовёт loop(); тут же отправка своего 'move' 20 Гц
  now(),                       // оценка серверного времени в мс
  reportShot(ammoIdx, origin, dir, chg),
  reportHit(victim, part, dmg, ammoIdx),
  // Накрытие чужих игроков считает сам стрелявший — ровно той же формулой
  // splashDamage(), что и всё остальное. NET перебирает NETP-позиции и шлёт 'boom'.
  reportBoom(pos, R, maxDmg, fall, coverMul),
  reportBurn(victim, total),
  reportPick(i),
  reportBotHit(botId, dmg, part)   // урон боту заявляем хосту (мы не хост)
};
```

Также обязан отдавать наружу: `netConnect(url,name)`, `netDisconnect()`, `netIsOn()`.

### `src/94_netplayers.js` — удалённые игроки и реплики ботов (агент **N3**)

```js
const NETP = {
  ensure(id, team, name),      // создать модель (mkSniper с цветом команды)
  drop(id),
  applySnap(list, kServer),    // положить кадр в буферы
  applyBots(list, kServer),
  update(dt),                  // интерполяция с задержкой 120 мс + анимация поз
  segHit(p0, dir, len),        // -> {t, part, id} | null — попадание пули в удалённого
  reset()
};
```

`segHit` обязан использовать те же габариты, что `segPlayer` в `60_weapon.js`
(голова — сфера r=0.235 на высоте `h-0.20`, корпус — OBB 0.33 × 0.40h × 0.27).

## 8. Сервер — `net/server.js` (агент **N1**)

Один процесс на чистом Node (модули `http`, `crypto`, `net`), без зависимостей:

* HTTP: отдаёт `dm_duel_v3.html` и файлы проекта (тот же подход, что в `tools/serve.js`).
* WebSocket на том же порту через `upgrade`: рукопожатие по RFC 6455
  (`Sec-WebSocket-Accept` = base64(sha1(key + GUID))), разбор кадров с длинами 7/16/64 бит,
  обязательное снятие маски с клиентских кадров, сборка фрагментов, ответ на `ping`,
  корректное закрытие. Кадры от клиента без маски — разрыв соединения (требование RFC).
* Комната: до `RULES.slots` участников, распределение по командам поровну.
* Авторитет: `hp`, `kills`, `deaths`, счёт команд, респавн через `RULES.respawn` секунд,
  пикапы с временем возврата, выбор хоста ботов.
* Валидация заявок — §1. Отклонённые заявки логируются в консоль сервера, клиенту шлётся `err`
  только при грубом нарушении.
* Порт по умолчанию 8177, переопределяется `--port` или `PORT`.
* При старте печатает готовые адреса: `http://localhost:PORT` и адреса всех сетевых
  интерфейсов машины, чтобы друзьям было что скопировать.

Константы правил объявляются в самом сервере:
```js
const RULES = { slots:8, players:4, goal:20, respawn:3.0, tick:20, timeout:10000 };
```

# 9. Уточнения после первой ревизии

Первая реализация разошлась с контрактом в шести местах, потому что §1–§8 не дописывали
до конца, кто владеет здоровьем и что происходит с самоуроном. Ниже — обязательные уточнения.
Они имеют приоритет над §3.

## 9.1 Здоровьем владеет ТОЛЬКО сервер

При `NET.on` клиент **не имеет права** менять `player.hp` сам — ни от пули, ни от фугаса
под ногами, ни от горения, ни от аптечки. Любое такое изменение превращается в заявку,
а здоровье приходит обратно авторитетным значением в `dmg`.

Причина: сейчас `hurtPlayer()` и `tickPlayerBurn()` списывают здоровье локально, а `netDamage()`
ставит серверное значение. Первое же чужое попадание откатывает всё локально списанное вверх.
Обратный случай хуже: при локальной смерти клиент считает себя мёртвым, а комната — живым,
и игрок становится «призраком», который стоит на месте и не может возродиться.

Новое сообщение, клиент → сервер:
```
{t:'self', d, c}      d — урон себе, c — причина: 'frag' | 'burn' | 'fall'
```
Сервер применяет его как обычный урон с `from = -1`, ограничивая величину за тик по причине,
и рассылает результат существующим `dmg` / `kill`.

## 9.2 Лечение тоже авторитетное

Пикап применяется **только после подтверждения сервера**. Клиент шлёт `pick`, прячет предмет
(иначе подбор ощущается вязким) и ждёт ответа; эффект накладывается лишь если `by === NET.id`.
Ответ расширяется полем `hp`:
```
{t:'pick', i, by, at, hp}     hp — авторитетное здоровье получателя после аптечки
```
Серверу нужна таблица пикапов (тип и координаты) — дублируется так же, как уже продублированы
`AMMO` и точки респавна, с тем же комментарием «обязаны совпадать с `45_map.js`».
Откат возврата брать по типу: аптечка большая 22 с, малая 13 с, патроны 18 с.

## 9.3 Боеприпас в заявке — тот, которым выпущена пуля

`wpn.idx` меняется мгновенно, а пуля летит до полусекунды. В `hit` и в заявке об уроне боту
обязан уходить индекс боеприпаса **пули**, а не текущего выбора. Для этого `spawnBullet`
сохраняет в пуле индекс, и он передаётся дальше.

Сигнатуры уточняются:
```js
NET.reportHit(victim, part, dmg, ammoIdx)        // ammoIdx — от пули
NET.reportBotHit(botId, dmg, part, ammoIdx)      // добавлен четвёртый аргумент
```

## 9.4 Боты обязаны видеть всех игроков, а не только локального

Сейчас `70_ai.js` знает только про `player`, поэтому в сети боты опасны исключительно хосту,
а остальные трое для них не существуют. Это делает половину режима бессмысленной.

Требование: при `NET.on` у хоста боты выбирают цель среди **локального игрока и всех живых
удалённых** (позиции берутся у `NETP`), учитывая команду — по своим не стреляют. Урон игроку
от бота заявляет хост сообщением `bhit`. Промахи, телеграф и вся остальная логика — как есть.

## 5-бис Атрибуция убийств ботов

`Enemy.die()` сейчас безусловно начисляет фраг локальному игроку, пишет в киллфид и при
достижении цели зовёт `endGame(true)`. В сети хост попадает туда по **чужой** заявке, то есть
получает фраг за бота, которого убил другой, и может закончить матч себе «победой» посреди боя.

Требование: при `NET.on` `die()` не начисляет локальный фраг, не пишет ленту от первого лица
и **не зовёт** `endGame`. Конец матча в сети — исключительно по серверному `score`.

## 9.5 Мелкие обязательные поправки

| Где | Что |
|---|---|
| `welcome` | добавить `respawn` (секунды) — клиент не должен дублировать константу |
| `ping` | добавить `rtt` — сервер уже считает его в `pong`, но никому не отдаёт |
| `snap`, запись игрока | добавить `tm` — команда; без неё неизвестный игрок молча становится BLU и делается непростреливаемым |
| `slots` в `welcome` | это **свободные** слоты, они же число ботов (`RULES.slots` минус люди) |
| `resp` | клиент обязан проверить координаты на `isFinite`, иначе `NaN` расползается по всей физике |
| респавн в сети | локальный таймер не поднимает игрока — только серверный `resp`; точка выбирается по команде (`SPAWNS_RED` для RED) |
| `resp` при входе | не рассылать входящему игроку до старта боя |
| таблица обработчиков на сервере | объявить через `Object.create(null)`: сейчас тип `__proto__` рвёт соединение |
| `p.s` в `SRV_onMove` | обновлять **после** проверок, иначе битый пакет съедает номер и честный следующий отбрасывается |
| заявка об уроне боту | проверять до пересылки: жив ли заявитель, темп, потолок урона |
| кадр ботов на сервере | протухает через ~1 с; иначе боты «живут» неподвижно после выхода хоста |
| число ботов | пересматривать на `join`/`leave`, а не только в `startGame` |
| `m.ver` в тексте ошибки | чистить, как чистится имя игрока |

Добавить в таблицу §3 «Сервер → клиент» пропущенную строку:
```
{t:'hit', i, v, p, d, a}      пересылка заявки об уроне боту хосту; i — кто стрелял
```
и расширить перечисление части тела до `'head' | 'body' | 'legs' | 'splash' | 'burn'`.
