# `net/server.js` — сервер комнаты DM_DUEL v3

Один процесс на чистом Node. Зависимостей нет, `npm install` не нужен и не будет нужен.
Отдаёт и саму игру по HTTP, и WebSocket на том же порту.

```bash
node net/server.js              # порт 8177
node net/server.js --port 9000
PORT=9000 node net/server.js
```

Приоритет порта: `--port` → `PORT` → 8177. При старте печатаются готовые адреса
для локальной сети и подсказка про туннель — их можно сразу кидать друзьям.

Состояние комнаты видно живьём: `http://localhost:8177/__status` (JSON).

## Что сервер решает

Модель авторитета — [NETCONTRACT.md](../NETCONTRACT.md) §1 и §9. Сервер **не** пересчитывает
мир: рельефа, коллизий и баллистики здесь нет. Он ведёт `hp`, `kills`, `deaths`, счёт команд,
респавн, пикапы и выбор хоста ботов, а заявки клиентов проверяет на правдоподобность.

**Здоровьем владеет только сервер** (§9.1–9.2). Клиент не списывает и не поднимает `hp` сам
ни от чужой пули, ни от собственного фугаса, ни от аптечки: любое изменение — это заявка,
а обратно приходит авторитетное число в `dmg` или в `pick`.

```js
const RULES = { slots:8, players:4, goal:20, respawn:3.0, tick:20, timeout:10000 };
```

* до `RULES.players` живых игроков, пятому — `err` и разрыв;
* команды делятся поровну (при равенстве новичок идёт в BLU);
* свободные слоты до `RULES.slots` — боты; их держит **хост ботов** (игрок с наименьшим id),
  при его уходе сервер рассылает `host` следующему;
* цель матча `RULES.goal`; когда она взята, сервер ждёт 10 секунд и начинает новый раунд —
  обнуляет счёт, `kills`/`deaths` и поднимает всех (рассылается обычный `score`, новых
  типов сообщений для этого не вводилось).

## Проверка заявок

| Что проверяется | Порог |
|---|---|
| стрелок жив, жертва жива, это не свой | — |
| урон не выше максимума типа боеприпаса (с учётом крита) | `AMMO[a].dmgMax` / `headMax` / `splashMax` × 1.06 |
| темп стрельбы | не чаще `max(cd, bolt)` × 0.85 |
| ствол там же, где заявленная позиция | ≤ 6 м |
| дистанция до жертвы | ≤ 300 м (диагональ зоны 2 × 88 м ≈ 249 м плюс запас) |
| попадание опирается на выстрел | тот же тип, не старше 3 с |
| цель лежит вдоль луча выстрела | отклонение ≤ 3.5 м + 0.06 × дистанция |
| накрытие фугасом | ≤ `splashR` × 1.25, урон ≤ `splashMax` × 1.06 |
| горение | суммарно ≤ `burnDps × burnTime` × 1.06 |
| самоурон (`self`) | потолок и темп по причине: `frag` 61 и 70/с, `burn` 8.3 и 17.6/с, `fall` 100 и 100/с |
| пикап (`pick`) | индекс из таблицы, заявитель жив и стоит рядом: ≤ 6 м по горизонтали и ≤ 4 м по высоте |
| урон боту (`hit` с `v:'b…'`) | заявитель жив, был выстрел того же типа не старше 3 с, не больше 8 заявок на выстрел, потолок урона тот же |
| урон игроку от бота (`bhit`) | ≤ 190 и только от хоста |
| `bots` | только от хоста |

Заявка об уроне боту проходит **те же** проверки, что и заявка о попадании в игрока, и
только потом пересылается хосту: иначе «курьерская» ветка была бы дырой, через которую
труп раздаёт девять тысяч урона и это даже не считается отклонением. Луч по боту не
сверяется — их позиции у сервера чужие и свежие только у хоста.

Отклонённые заявки печатаются в консоль сервера. Повтор того же вида нарушения внутри
полусекунды сворачивается в счётчик («ещё N × …»), новый вид печатается всегда.
Клиенту `err` уходит только при грубом нарушении: больше 100 отклонений за 10 секунд —
это уже не пинг, и соединение закрывается кодом 4003.

**Дружественного огня нет.** Прямые попадания, накрытие и поджог по своей команде
отклоняются: иначе тиммейт, перекрывший линию, превращает дуэль в фарм.

Значения боеприпасов продублированы в сервере константой `AMMO` и **обязаны совпадать**
с массивом `AMMO` в `src/10_core.js`; `headMax` повторяет `WPN_headDamage()` из
`src/60_weapon.js`. Правишь баланс там — правь и здесь, иначе сервер начнёт резать
честные попадания.

Так же продублированы точки респавна (`SPAWNS` ← `SPAWNS_BLU`/`SPAWNS_RED`) и таблица
пикапов (`PICKS` ← `PICKUPS`) из `src/45_map.js`. У пикапов **обязаны совпадать тип,
координаты и порядок**: клиент шлёт индекс в массиве, и разъехавшийся порядок означает,
что заявка на аптечку у базы вылечит того, кто стоит на крыше форта. `heal` повторяет
`updatePickups()` из `75_combat.js` (большая аптечка 50, малая 25, патроны 0 — их клиент
считает сам, они не спорны), `cd` повторяет `MAP_pu()`: большая 22 с, малая 13 с,
патроны 18 с. Высоты в `PICKS` посчитаны один раз по `terrainH()` — рельефа у сервера
нет, и нужны они только чтобы отличить ярус.

## Протокол

Ровно [NETCONTRACT.md](../NETCONTRACT.md) §3 с уточнениями §9, те же имена полей.
Неизвестный тип сообщения игнорируется молча — **включая** `__proto__`, `constructor`,
`valueOf` и прочие имена из `Object.prototype`: таблица обработчиков объявлена через
`Object.create(null)`, поэтому такой тип не подставляет чужую функцию и не рвёт соединение.

Что добавилось к §3 (см. §9):

```
клиент → сервер   {t:'self', d, c}          c — 'frag' | 'burn' | 'fall'
сервер → клиент   {t:'welcome', …, respawn} секунды до подъёма — константа сервера
сервер → клиент   {t:'ping', k, rtt}        rtt — измеренный сервером круговой ход, мс
сервер → клиент   {t:'snap', …, p:[{…,tm}]} tm — команда игрока
сервер → клиент   {t:'pick', i, by, at, hp} hp — авторитетное здоровье поднявшего
```

`self` применяется как обычный урон с `from = -1`; смерть от него — обычный `kill`
с `k = -1` и `p` равным причине. Часть тела в `dmg` / `kill` расширена до
`'head' | 'body' | 'legs' | 'splash' | 'burn' | 'frag' | 'fall'`.

Три места, где §3 оставляет свободу, разрешены так:

1. **`welcome.slots` — это число ботов** (свободные слоты), то самое `NET.botCount`.
   Дальше клиент пересчитывает его сам по `join` / `leave`:
   `botCount = RULES.slots − количество игроков`.
2. **`snap.p` содержит и самого получателя.** Снапшот сериализуется один раз на всю
   комнату, клиент просто пропускает запись со своим `id`. `snap.b` отсутствует (`null`),
   пока хост не прислал ни одного кадра ботов.
3. **Урон боту** (`hit` с `v` вида `'b3'`) сервер пересылает хосту тем же типом `hit`,
   добавив поле `i` — id стрелявшего: `{t:'hit', i, v:'b3', p, d, a}`. Это единственное
   сообщение, которого нет в списке §3 «сервер → клиент», и оно нарочно названо так же,
   как ретрансляция чужого выстрела `{t:'shot', i, …}`.

Ещё несколько мелочей, о которых стоит знать клиенту:

* `dmg.from` — **id** стрелка (не позиция); для урона от бота, от огня и от самоурона
  приходит `-1`;
* при каждом респавне всем уходит `{t:'resp', i, x, y, z}` — стартовая точка тоже
  назначается сервером. Точки взяты из `SPAWNS_BLU`/`SPAWNS_RED` в `45_map.js`;
  доводит игрока по месту всё равно клиентская физика. **Входящему игроку его
  собственный `resp` не рассылается**: он ещё в лобби, боя не начинал, и применять
  координаты ему некуда — остальные при этом узнают, где он появился;
* `p.s` в `move` сервер запоминает только после всех проверок: битый пакет не съедает
  номер, и следующий за ним честный не отбрасывается как «старый»;
* кадр ботов **протухает за 1 секунду**. Хост ушёл или замолчал — `snap.b` снова `null`,
  и боты не остаются неподвижными мишенями. Как только хост заговорил, они возвращаются.

Пикапы сервер арбитрирует по индексу: кто успел, тот и взял, остальным приходит `pick`
с настоящим владельцем и временем возврата `at`. Аптечка применяется тем же ответом:
поднявший получает `hp` (большая +50, малая +25, потолок 100), и аптечка гасит серверное
горение, как в одиночной игре. Опоздавшему `hp` не шлётся — лечится только тот, кому
предмет достался. Откаты — по типу предмета, теми же числами, что в `45_map.js`.

## WebSocket

Рукопожатие и разбор кадров написаны вручную по RFC 6455:

* `Sec-WebSocket-Accept = base64(sha1(key + 258EAFA5-E914-47DA-95CA-C5AB0DC85B11))`;
* длины 7 / 16 / 64 бит, сборка фрагментов, `ping` → `pong`, корректный `close` с кодом;
* кадр от клиента **обязан** быть маскирован — немаскированный рвёт соединение (1002);
* расширения (`permessage-deflate`) не подтверждаются, поэтому RSV-биты обязаны быть нулевыми;
* серверные кадры уходят **без** маски;
* лимиты: кадр 512 КБ, собранное сообщение 1 МБ, разбираемый JSON 256 КБ,
  исходящая очередь 4 МБ (клиент, который не читает, отключается), всего 24 сокета.

Всё, что приходит по сети, рвёт **одно соединение**, а не процесс: битый JSON, обрезанный
кадр, гигантская заявленная длина, мусорные типы полей, обрыв посреди кадра. На самый
крайний случай стоит `uncaughtException`, который громко пишет в лог и оставляет комнату жить.

## Как это проверялось

Тестовые клиенты писались на встроенном в Node 22 глобальном `WebSocket` (для сценариев)
и на голом `net.Socket` с ручной сборкой кадров (для протокола и для заведомо кривых
кадров, которых нормальный клиент не пошлёт). Прогоны:

* **сценарий комнаты, 48 проверок** — вход четверых, поровну по командам, `move`/`snap`
  на 20 Гц, ретрансляция выстрела, попадание и авторитетный `hp`, отклонения (темп, урон,
  свои), смерть, `kill`, `score`, ранний `resp`, респавн, фугас на двоих, горение порциями,
  спор за пикап, боты от хоста и отказ не-хосту, пересылка урона боту, `bhit`, уход хоста
  и переизбрание, отключение, `ping`;
* **кадры, 16 проверок** — рукопожатие, длины 7/16/64 бит (в том числе 120 КБ одним кадром),
  фрагментация (в том числе ~90 КБ пятью фрагментами), `ping`/`pong` с телом, отсутствие
  маски в серверных кадрах, `close` с кодом;
* **устойчивость, 31 проверка** — битый JSON, пустое сообщение, не-объекты, мусорные типы
  полей, невалидный UTF-8, двоичный кадр, JSON с 400 уровнями вложенности, немаскированный
  кадр, RSV, неизвестные опкоды, фрагментированный управляющий кадр, `continuation` без
  начала, чередование фрагментов, длина 2 МБ, 64-битная длина со старшими битами, обрыв
  посреди кадра, уход до `hello`, 3000 сообщений подряд, шторм ложных заявок, обход корня
  в HTTP (`..`, `%2e%2e`, `....//`);
* **долгие сценарии, 14 проверок** — отказ пятому игроку, автоподъём молчащего клиента
  через `RULES.respawn`, взятие цели с обнулением счёта новым раундом, отключение молчуна
  по `RULES.timeout`;
* **§9, 68 проверок** — `welcome.respawn`, `ping.rtt`, `tm` в снапшоте, отсутствие
  собственного `resp` у входящего; типы `__proto__` / `constructor` / `valueOf` /
  `toString` / `hasOwnProperty` и ещё четыре имени из `Object.prototype` (соединение живо,
  обработчик не подменён); битый `move` с большим номером и честный следом за ним;
  самоурон всех трёх причин, срез по потолку, шторм из сорока заявок (заявлено 200 урона,
  снято 8), причина из прототипа, смерть с `k = -1` и `p = 'fall'` без фрага кому-либо;
  аптечки — малая 25 и большая 50, `hp` в ответе, откат 13 с, спор двоих за один предмет
  в одном тике, отказ издалека и по индексу вне таблицы; заявка об уроне боту без выстрела,
  с запредельным уроном и от мёртвого; протухание кадра ботов и его возвращение;
  чистка `m.ver` в тексте ошибки и в логе.

Итого **177 проверок, 0 провалов** на текущей версии.
